Each exercise poses a problem; its answer, and what the installed data gives back, are in the `.sql` file.
The data is the `3m` edition, three months of flights from 2025-10-01, and the database's today, `bookings.now()`, is 2025-12-01; the views read the names in the language `bookings.lang()` returns, `en`.
A day or a month is a UTC one, unless an exercise says it is an airport's local one: a bound on a `timestamptz` is written `TIMESTAMPTZ '2025-10-01 00:00:00+00'`, and a day or a month is taken `AT TIME ZONE 'UTC'`, so that the answer does not depend on the session's time zone, which psql and a JDBC connection set differently.

==== DEMODB_SCHEMA_A_06: the passengers still to board the flights now boarding

For the flights whose status is `Boarding`, list the sold segments whose passenger has no boarding time yet, those with no boarding pass included.
Show the flight, the ticket, the passenger's name, the seat and the boarding number, ordered by flight and ticket.

.`__/03_advanced.sql`, DEMODB_SCHEMA_A_06
[%collapsible]
====
[source,sql]
----
SELECT f.flight_id, s.ticket_no, t.passenger_name, bp.seat_no, bp.boarding_no
FROM flights f
         JOIN segments s ON s.flight_id = f.flight_id
         JOIN tickets t ON t.ticket_no = s.ticket_no
         LEFT JOIN boarding_passes bp ON bp.ticket_no = s.ticket_no AND bp.flight_id = s.flight_id
WHERE f.status = 'Boarding'
  AND bp.boarding_time IS NULL
ORDER BY f.flight_id, s.ticket_no
