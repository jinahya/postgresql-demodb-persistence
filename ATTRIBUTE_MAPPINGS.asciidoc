Every attribute of `bookings` which maps a column, grouped by its column type, its attribute type and its
converter: 69 attributes over the 9 tables and 3 views mapped (45 of tables, 24 of views). The column type is
`INFORMATION_SCHEMA.COLUMNS`', without the length; for the declared types, see
link:COLUMN_TYPES.asciidoc[Column Types]. Every table and view of `bookings` is mapped, and every column of each has
exactly one attribute.

No column is `bytea`, `uuid`, `xml`, `json`, an enumerated type or a domain, and no attribute is `@Lob` or
`@Enumerated`.

Each foreign-key column has an attribute of its key's type. `flights.route_no` refers to `routes` by no foreign
key: `routes` has no primary key, and a flight's route is the row whose `validity` holds its
`scheduled_departure`, as `timetable` joins them.

[[composite-keys]]
== Composite keys

The four tables of composite keys map them in `@EmbeddedId`s of the `@Embeddable` `*Id` classes; their attributes
are among the rows above.

[cols="2,3,5",options="header"]
|===
| Table | Key class | Columns

| `routes` | `RouteId` | `route_no`, `validity`
| `seats` | `SeatId` | `airplane_code`, `seat_no`
| `segments` | `SegmentId` | `ticket_no`, `flight_id`
| `boarding_passes` | `SegmentId`, the key of the segment it references | `ticket_no`, `flight_id`

|===

The specification does not have `@Convert` on an attribute of an identifier, so `RouteId`'s `validity` is not
portable; Hibernate ORM, which the module targets, maps it.

[[json]]
== JSON

`airplanes_data.model` and `airports_data.airport_name`, `city` and `country` are `jsonb` objects of a name per
language, `en` and `ru` (`{"en": "Airbus A320neo", "ru": "Аэробус A320neo"}`). Each is read through
`jinahya-persistence-more`'s `JsonpAttributeConverter.OfString.OfJsonObject`, which reads one JSON object, but to
three types:

[cols="3,2,5",options="header"]
|===
| Columns | Java type | Mapping

| `airplanes_data.model`, `airports_data.airport_name`
| `JsonObject`
| `@Convert(converter = JsonpAttributeConverter.OfString.OfJsonObject.class)`, the object as it is.

| `airports_data.city`
| `Map<Locale, String>`
| `@Convert(converter = LocaleStringMapAttributeConverter.class)`; each key a `Locale` of its language, through
`LocaleStringAttributeConverter.OfLanguage`.

| `airports_data.country`
| `List<LocaleName>`
| `@Convert(converter = LocaleNameListAttributeConverter.class)`; a `LocaleName` per language, in the order of the
converter's `ORDER`, so that the same names read twice are equal lists.

|===

The views `airplanes` and `airports` read the same columns as `text`, the name in the session's language
(`bookings.lang()`), and map them as `String`s. `stringtype=unspecified` on the JDBC URL of the `it` unit sends the
text a converter writes untyped, so that the server casts it to `jsonb`, `point` or `tstzrange`.

[[enums]]
== Enums

[cols="3,2,3,4",options="header"]
|===
| Column | Java type | Mapping | Note

| `flights.status`, `timetable.status`
| `MappedFlight.FlightStatus`
| `@Convert(converter = FlightStatusConverter.class)`
| `text`; `flight_status_check` allows `Scheduled`, `On Time`, `Delayed`, `Boarding`, `Departed`, `Arrived` and
`Cancelled`. `On Time` is not a Java identifier, and none is a constant's name in upper case, so `@Enumerated`
cannot read them. The enum is an `AttributeEnum.OfString` whose attribute value is the text (`ON_TIME` is
`On Time`), and the converter, nested in `MappedFlight`, an `AttributeEnumConverter.OfString`, of
`jinahya-persistence-more`. `timetable`'s is the view's copy, which carries no check.

| `seats.fare_conditions`, `segments.fare_conditions`
| `MappedSeat.FareConditions`
| `@Convert(converter = FareConditionsConverter.class)`
| `text`; `seat_fare_conditions_check` and `segments_fare_conditions_check` allow `Economy`, `Comfort` and
`Business`. As `FlightStatus`; one enum, nested in `MappedSeat`, serves both tables.

|===

[[converters]]
== Converters

Every converter which is not an enum's, nor a `jsonb` column's (see <<json>>), with the attributes it converts:

[cols="3,2,4,4",options="header"]
|===
| Converter | Java type | Columns | Note

| `ZoneIdStringAttributeConverter`
| `ZoneId`
| `airports.timezone`, `airports_data.timezone`
| `jinahya-persistence-more`'s; `text` holding a region id (`Europe/Moscow`), read with `ZoneId.of`.

| `PointAttributeConverter`
| `List<Double>`
| `airports.coordinates`, `airports_data.coordinates`
| The module's; `point`, through its text `(x,y)`, as `[x, y]`: the longitude and the latitude. No provider maps a
native `point`: Hibernate Spatial needs PostGIS `geometry`, which the database has not.

| `RouteId.ValidityConverter`
| `Instant[]`
| `routes.validity`
| The module's; `tstzrange`, through its text, as `[lower, upper]`. Only a range with both bounds, the lower
inclusive and the upper exclusive, is converted, the shape of every period the database holds; any other is
rejected. An attribute of the `@EmbeddedId`; see <<composite-keys>>.

|===

`routes.days_of_week` and `routes.duration` need no converter, but Hibernate ORM's `@JdbcTypeCode`
(`SqlTypes.ARRAY`, `SqlTypes.INTERVAL_SECOND`); Jakarta Persistence has no mapping of an array or an interval of its
own.
